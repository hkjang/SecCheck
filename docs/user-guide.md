# SecCheck 사용자 실무 가이드 (User Guide)

`SecCheck`는 심의 요청자, 보안 담당자, 승인자가 하나의 시스템에서 유기적으로 소통하며 보안성 심의를 완결할 수 있도록 지원합니다.

---

## 1. 역할별 핵심 업무 흐름

```
[심의 요청자 (Requester)]
   │
   ├─► 1. 신규 심의 요청 등록 (서비스 정보 & Rule Engine 조건)
   ├─► 2. 배정된 체크리스트 작성 & 증적 파일 암호화 업로드
   └─► 3. 심의 제출 (서버 검증: N/A 사유, 필수 증적 누락 체크)
            │
            ▼
[보안 담당자 (Security Reviewer)]
   │
   ├─► 4. 보안 검토 Queue에서 건 선택 후 "검토 시작"
   ├─► 5. 항목별 검토 결과 입력 (적합 / 조건부 / 미흡 / 부적합 / N/A 인정)
   ├─► 6. 필요 시 항목별 "보완 요청" 발행 ───┐
   │                                          │ (보완 조치 루프)
   │        ┌─────────────────────────────────┘
   │        ▼
   │   [요청자] 보완 조치 내용 작성 및 재제출
   │        │
   │        ▼
   └─► 7. 보완 조치 검증 완료 후 "검토 완료"
            │
            ▼
[승인자 (Approver)]
   │
   └─► 8. 승인 대기 건 최종 승인 (또는 반려) 및 이력 불변 보존
```

---

## 2. 심의 요청자 (Requester) 실무

### 📝 1. 신규 심의 요청 생성
1. 대시보드 또는 심의 목록에서 `신규 심의` 버튼을 클릭합니다.
2. **서비스 기본정보**를 입력합니다:
   - 서비스명, 담당 부서, 서비스 설명, 서비스 유형(대내/대외/관리자/배치), 신규·변경 구분, 오픈 예정일
3. **적용 조건 (Rule Engine)**을 체크합니다:
   - 관리자 페이지 여부, 개인정보/신용정보 처리 여부, 클라우드/Docker/K8s 사용 여부, 외부 연계 및 인터넷 통신 여부
4. `심의 생성 및 항목 배정` 버튼을 클릭하면, 등록된 최신 템플릿에서 조건에 맞는 항목들이 스냅샷으로 자동 배정됩니다.

### ✍️ 2. 체크리스트 작성 및 증적 첨부
- **적용 여부 (`Y` / `N` / `N/A`)**:
  - `Y`: 요건을 충족하는 경우 선택하고 자체 판단(`적합`) 및 적용 현황을 작성합니다.
  - `N/A`: 해당 요건이 서비스에 적용되지 않는 경우 선택하며, **N/A 사유를 반드시 입력**해야 제출이 가능합니다.
- **실시간 자동 저장**: 입력 중 1.2초 후 자동으로 백그라운드에 저장되며 우측 상단에 `✓ 자동 저장` 상태가 표시됩니다.
- **증적 파일 업로드**:
  - `증적 첨부` 섹션에서 파일을 선택하고 설명을 입력한 뒤 `암호화 업로드`를 클릭합니다.
  - 파일은 확장자와 Magic/MIME 검증 후 AES-256-GCM으로 암호화 저장됩니다.
  - 파일 변경 시 `새 버전` 버튼으로 이력을 덮어쓰지 않고 버전별로 보존할 수 있습니다.

### 🚀 3. 심의 제출 및 누락 검증
- 모든 필수 항목을 작성한 후 우측 상단의 `제출` 버튼을 클릭합니다.
- **서버 제출 검증**:
  - N/A 사유 누락, 필수 증적 미첨부, 미작성 항목이 발견되면 모달 팝업으로 누락 목록을 정확히 안내하여 결함을 사전 예방합니다.

### 🔄 4. 보완 요청 대응 및 재제출
- 보안 담당자가 보완을 요청한 항목에는 주황색 `보완 요청` 뱃지가 표시됩니다.
- 보완 사유를 확인하고 조치 내용 작성 및 추가 증적을 첨부한 뒤 `조치 완료`를 누르고 `재제출`합니다.

## 3. 보안 담당자 (Security Reviewer) 실무

### 🛡️ 1. 보안 검토 Queue (`/security`)
- 제출(`SUBMITTED`) 또는 재제출(`RESUBMITTED`)된 심의 건을 확인하고 `검토` 버튼을 누릅니다.
- 상단의 `검토 시작` 버튼을 누르면 상태가 `REVIEWING`으로 전환됩니다.

### 🔍 2. 항목별 검토 및 판정
- 항목을 선택하고 우측의 가이드, 법적 근거, 첨부된 증적 파일을 검토합니다.
- `보안 담당자 검토` 섹션에서 다음을 판정합니다:
  - **최종 적용 여부**: 작성자 판단 유지 또는 `Y`/`N`/`N/A`로 조정
  - **검토 결과**: `적합(COMPLIANT)`, `조건부 적합(CONDITIONAL)`, `미흡(INSUFFICIENT)`, `부적합(NON_COMPLIANT)`, `N/A 인정(NA_ACCEPTED)`, `재확인(RECHECK)`
  - **증적 적정성**: `적정(ADEQUATE)`, `일부 보완(PARTIAL)`, `부적정(INADEQUATE)`
  - **검토 의견 및 후속조치** 작성 후 `검토 저장` 클릭

### ⚠️ 3. 항목 보완 요청 및 검증
- 미흡한 항목은 `보완 요청` 버튼을 눌러 보완 사유와 완료 기한을 지정합니다.
- 요청자가 조치를 완료하면 `조치 검증` 버튼을 눌러 상태를 `VERIFIED`로 변경합니다.
- 모든 항목 검토가 끝나면 `검토 완료` 버튼을 누릅니다.

---

## 4. 승인자 (Approver) 실무

- 관리자 설정에서 `승인 프로세스`가 켜져 있는 경우, 검토가 완료된 건은 `APPROVAL_PENDING` 상태로 승인자에게 전달됩니다.
- 심의 상세 상단의 `최종 승인` 또는 `반려` 버튼을 클릭하고 의견을 남겨 의사결정을 완료합니다.

---

## 5. 심의 결과물 내보내기 (Export)

심의 상세 상단의 내보내기 버튼을 통해 3가지 형식의 최종 보고서를 다운로드할 수 있습니다:

| 포맷 | 파일 확장자 | 내용 및 용도 |
| :--- | :--- | :--- |
| **Excel** | `.xlsx` | 전 항목 체크리스트, 자체 판단, 검토 결과, 코멘트가 서식화된 엑셀 보고서 |
| **PDF** | `.pdf` | 감사 및 대외 제출용 공식 보안성 심의 완료 증명서 (A4 규격) |
| **ZIP** | `.zip` | 심의 보고서와 암호화 복호화된 전체 첨부 증적 파일 압축 패키지 |
