# SecCheck 사용자 실무 가이드 (User Guide)

`SecCheck`는 심의 요청자, 보안 담당자, 승인자가 하나의 시스템에서 유기적으로 소통하며 보안성 심의를 완결할 수 있도록 지원합니다.

---

## 1. 역할별 핵심 업무 흐름

```
[심의 요청자 (Requester)]
   │
   ├─► 1. 신규 심의 요청 등록 (서비스 정보 & Rule Engine 조건)
   ├─► 2. 배정된 체크리스트 작성 & 증적 파일 암호화 업로드
   └─► 3. 심의 제출 (서버 검증: N/A 사유, 필수 증적 누락 체크)
            │
            ▼
[보안 담당자 (Security Reviewer)]
   │
   ├─► 4. 보안 검토 Queue에서 건 선택 후 "검토 시작"
   ├─► 5. 항목별 검토 결과 입력 (적합 / 조건부 / 미흡 / 부적합 / N/A 인정)
   ├─► 6. 필요 시 항목별 "보완 요청" 발행 ───┐
   │                                          │ (보완 조치 루프)
   │        ┌─────────────────────────────────┘
   │        ▼
   │   [요청자] 보완 조치 내용 작성 및 재제출
   │        │
   │        ▼
   └─► 7. 보완 조치 검증 완료 후 "검토 완료"
            │
            ▼
[승인자 (Approver)]
   │
   └─► 8. 승인 대기 건 최종 승인 (또는 반려) 및 이력 불변 보존
```

---

## 2. 심의 요청자 (Requester) 실무

### 📝 1. 신규 심의 요청 생성

서비스 특성 토글을 조정하면 화면 아래 **배정될 체크리스트 미리보기**가 즉시 갱신됩니다. 생성 전에 몇 개 항목을 어느 템플릿에서 받게 되는지 확인하고, 특성 입력이 맞는지 점검하세요.
1. 대시보드 또는 심의 목록에서 `신규 심의` 버튼을 클릭합니다.
2. **서비스 기본정보**를 입력합니다:
   - 서비스명, 담당 부서, 서비스 설명, 서비스 유형(대내/대외/관리자/배치), 신규·변경 구분, 오픈 예정일
3. **적용 조건 (Rule Engine)**을 체크합니다:
   - 관리자 페이지 여부, 개인정보/신용정보 처리 여부, 클라우드/Docker/K8s 사용 여부, 외부 연계 및 인터넷 통신 여부
4. `심의 생성 및 항목 배정` 버튼을 클릭하면, 등록된 최신 템플릿에서 조건에 맞는 항목들이 스냅샷으로 자동 배정됩니다.

### ✍️ 2. 체크리스트 작성 및 증적 첨부
- **적용 여부 (`Y` / `N` / `N/A`)**:
  - `Y`: 요건을 충족하는 경우 선택하고 자체 판단(`적합`) 및 적용 현황을 작성합니다.
  - `N/A`: 해당 요건이 서비스에 적용되지 않는 경우 선택하며, **N/A 사유를 반드시 입력**해야 제출이 가능합니다.
- **실시간 자동 저장**: 입력 중 1.2초 후 자동으로 백그라운드에 저장되며 우측 상단에 `✓ 자동 저장` 상태가 표시됩니다. 아직 저장되지 않은 입력이 있으면 `저장되지 않은 변경`으로 바뀌고, 그 상태에서 브라우저 탭을 닫으려 하면 경고가 표시됩니다. 즉시 저장하려면 `지금 저장`을 누르세요.
- **남은 작업 확인**: 항목 필터 드롭다운의 `미작성`, `증적 누락`, `보완 요청`, `답변 변경됨`, `이월 답변` 옆에 남은 건수가 함께 표시되므로 제출 전에 무엇이 남았는지 바로 알 수 있습니다.
- **재심의로 이월된 답변**: `재심의 복사`로 만든 심의는 이전 심의의 답변을 그대로 가져옵니다. 아직 다시 확인하지 않은 항목에는 보라색 `이월 답변` 표시가 남고, 저장하면 사라집니다. 검토자도 같은 표시를 보므로 **올해 아무도 다시 보지 않은 항목**이 무엇인지 알 수 있습니다. 증적은 이월되지 않습니다.
- **공동 작성자와 열람자**: 심의 상세의 `참여자` 카드에서 사람을 추가하며 `작성 가능`과 `열람 전용` 중에서 선택합니다. 현재 참여자와 권한이 표에 보이고, 필요 없어진 참여자는 `해제`로 접근을 회수합니다(해제도 감사로그에 남습니다). 열람 전용 참여자는 심의와 증적을 볼 수 있지만 체크리스트를 수정하거나 항목을 배정받을 수 없습니다.
- **참여자를 해제하거나 `열람 전용`으로 바꾸면**, 그 사람에게 배정돼 있던 항목의 담당자가 비워지고 몇 개가 풀렸는지 알려 줍니다. 담당자 이름만 남고 아무도 작업하지 않는 항목이 생기지 않습니다.
- **구축·개발·운영 담당자**: 신청서에 이름이 올라간 세 담당자는 별도 초대 없이 해당 심의를 열람하고 작성할 수 있으며, 목록과 `내 차례`에도 나타납니다. 항목 담당자로 지정할 수도 있습니다.
- **담당자 지정**: 항목마다 담당자를 지정할 수 있습니다. 지정하면 항목 목록에 담당자 배지가 붙고, 필터의 `내 담당 항목`으로 자기 몫만 볼 수 있습니다. 심의에 참여 중인 사람에게만 배정됩니다. 계정이 많은 설치에서는 선택 목록에 200명까지만 나오고, 그 위에 나타나는 검색창에 이름을 2자 이상 입력해 나머지를 찾습니다.
- **동시 편집**: 다른 사람이 같은 항목을 먼저 저장했다면 저장이 거부되고, 현재 저장된 내용과 저장한 사람을 보여줍니다. `최신 내용 불러오기`(내 입력을 버림) 또는 `내 내용으로 덮어쓰기` 중에서 선택하세요.
- **일괄 작성**: 항목 왼쪽 체크박스로 여러 항목을 고르면 하단에 작업 바가 나타납니다. `일괄 작성`으로 같은 적용 여부와 공통 사유를 한 번에 채울 수 있으며, 기본값은 **아직 작성하지 않은 항목만** 채웁니다. 이미 작성한 답변까지 바꾸려면 `덮어쓰기`를 켜세요. `담당자 배정` 탭에서는 답변을 건드리지 않고 담당자만 한 번에 지정합니다.
- **심의 결론 확인**: 심의 상단의 `심의 결론`에서 최종 결과와 최종 의견, 승인자의 승인·반려 코멘트와 일시를 확인합니다. 반려된 심의는 여기서 사유를 읽고 보완 후 다시 진행합니다.
- **내 후속조치**: 대시보드에 이행해야 할 후속조치가 심의를 가로질러 모여 표시됩니다. 심의 리포트는 보안 담당자용이라 요청자는 열 수 없으므로, 조치를 실제로 하는 쪽의 목록은 여기서 확인합니다.
- **조치 완료 보고**: 후속조치를 마쳤으면 해당 항목의 `조치 완료 보고`로 조치 내용을 남깁니다. 보고된 항목은 `조치 보고됨` 상태가 되고, 보안 담당자가 리포트에서 `이행 확인`을 해야 등록부에서 종료됩니다. 실제 조치는 서비스 담당 쪽에서 하고 확인은 보안 담당자가 하는 구조입니다. 보고하면 검토자에게 알림이 가고, 확인되면 보고한 사람에게 알림이 갑니다.
- **검토 결과 확인**: 검토가 끝난 뒤 항목 상세에서 보안 담당자의 판정, 검토 의견, 요청된 후속조치와 기한, 이행 여부를 그대로 볼 수 있습니다. 예전에는 이 내용이 검토자의 편집 화면 안에만 있어서 정작 조치를 해야 하는 쪽에서는 볼 수 없었습니다.
- **입력 길이**: 서비스명 200자, 부서 100자, 설명·현재 상태·조치 계획·N/A 사유·검토 의견·후속조치·최종 의견은 각각 4,000자까지 저장됩니다. 넘으면 저장 시 어느 항목이 긴지 알려 줍니다. 긴 로그나 설정 파일은 본문에 붙여넣기보다 증적 파일로 첨부하십시오.
- **증적 여러 건 첨부**: 파일 선택 창에서 여러 개를 한 번에 고를 수 있습니다. 하나의 보안요건을 화면 캡처 여러 장으로 증명할 때 한 번만 선택하면 되며, 각 파일은 별도 증적으로 저장됩니다. 일부가 확장자 정책에 걸려 실패해도 나머지는 그대로 저장되고 실패한 파일만 사유가 표시됩니다.
- **증적 미리보기**: 이미지 증적은 `미리보기` 버튼으로 내려받지 않고 화면에서 바로 확인합니다.
- **코멘트**: 항목에 남긴 코멘트는 대화의 반대편에게 알림으로 전달됩니다. 검토자의 질문은 작성자에게, 작성자의 답변은 검토자에게 갑니다.
- **증적 버전 이력**: 같은 증적을 `새 버전`으로 교체하면 이전 파일도 그대로 보관됩니다. `이력` 버튼을 누르면 버전별 업로더·시각·크기·SHA-256이 보이고, 이전 버전 파일도 내려받을 수 있습니다. 보존 기간이 지나 파기된 버전은 `파기됨`으로 표시되며 목록에는 남습니다.
- **증적 검사 상태**: 첨부한 증적에는 `검사 중`, `검사 완료`, `악성코드 탐지` 배지가 표시됩니다. 검사가 끝나기 전에는 다운로드와 제출이 제한되며, 보통 수 초 안에 완료됩니다.
- **증적 파일 업로드**:
  - `증적 첨부` 섹션에서 파일을 선택하고 설명을 입력한 뒤 `암호화 업로드`를 클릭합니다.
  - 파일은 확장자와 Magic/MIME 검증 후 AES-256-GCM으로 암호화 저장됩니다.
  - 파일 변경 시 `새 버전` 버튼으로 이력을 덮어쓰지 않고 버전별로 보존할 수 있습니다.

### 🚀 3. 심의 제출 및 누락 검증
- 모든 필수 항목을 작성한 후 우측 상단의 `제출` 버튼을 클릭합니다.
- **서버 제출 검증**:
  - N/A 사유 누락, 필수 증적 미첨부, 미작성 항목이 발견되면 모달 팝업으로 누락 목록을 정확히 안내하여 결함을 사전 예방합니다.
  - 목록의 항목명을 클릭하면 필터가 해제되면서 해당 항목이 펼쳐진 상태로 스크롤되므로, 긴 체크리스트에서도 바로 수정할 수 있습니다.

### 🕓 심의 이력

심의 상세 상단의 `이력` 버튼으로 그 심의에서 일어난 일을 시각순으로 확인합니다. 생성, 항목 작성, 증적 업로드, 제출, 보완 요청, 검토 판정, 승인·반려가 수행자와 함께 기록되며, 항목 단위 기록에는 항목코드가 표시됩니다. 심의를 볼 수 있는 사람이면 누구나 조회할 수 있습니다. 감사 권한이 있는 계정은 이력의 대상을 눌러 감사로그에서 그 대상의 전체 기록(변경 전·후 값 포함)으로 이동할 수 있습니다.

### 🔁 재심의 복사

연 1회 재심의처럼 이전 심의를 다시 진행할 때 `재심의 복사`를 사용합니다. 새 심의는 **오늘 게시된 템플릿**으로 구성되므로 이전과 항목이 다를 수 있으며, 복사 직후 다음을 안내합니다.

- 복사된 답변 수 (전체 항목 중)
- 신설되어 새로 작성해야 하는 항목 수
- 현재 템플릿에 없어 제외된 이전 항목 수

증적은 복사되지 않으므로 다시 첨부해야 합니다.

### 🔄 4. 보완 요청 대응 및 재제출
- 보안 담당자가 보완을 요청한 항목에는 주황색 `보완 요청` 뱃지가 표시됩니다.
- 보완 사유를 확인하고 조치 내용 작성 및 추가 증적을 첨부한 뒤 `조치 완료`를 누르고 `재제출`합니다.
- 보완 요청에는 `완료 예정일`이 반드시 지정됩니다. 기한 2일 전부터 담당자에게 알림이 가고, 기한이 지나면 심의 목록에서 지연으로 표시됩니다.

## 3. 보안 담당자 (Security Reviewer) 실무

### 🛡️ 1. 보안 검토 Queue (`/security`)
- 오픈 예정일이 3일 이내로 다가왔는데 심의가 끝나지 않았으면 신청자와 담당자 모두에게 `오픈 예정일 임박` 알림이 갑니다. 예정일이 지난 경우에도 알립니다.
- 제출·검토 중·승인 대기 상태로 3일 이상 멈춘 심의는 담당자에게 `심의 정체` 알림이 갑니다. 담당자가 없는 건들은 보안 담당자 전원에게 한 통으로 묶여 전달됩니다.
- 제출(`SUBMITTED`) 또는 재제출(`RESUBMITTED`)된 심의 건을 확인하고 `검토` 버튼을 누릅니다.
- **담당 검토자가 권한을 잃었거나 계정이 비활성화된 심의**는 다시 전체 검토자의 대기열에 나타납니다. 심의 상세에 `담당 검토자 권한 없음` 표시와 `검토 이어받기` 버튼이 뜨며, 이어받으면 담당자가 본인으로 바뀝니다. 승인 대기 건도 같습니다. 정체 알림도 처리할 수 없는 담당자 대신 검토자 전체에게 갑니다.
- 재제출된 심의는 알림 제목이 `심의 재제출`이며, **판정 이후에 답변이나 증적이 바뀐 항목 수**를 함께 알려 줍니다. 처음부터 다시 볼 필요 없이 그 항목만 확인하면 됩니다.
- 상단의 `검토 시작` 버튼을 누르면 상태가 `REVIEWING`으로 전환됩니다.

### 🔍 2. 항목별 검토 및 판정
- 항목을 선택하고 우측의 가이드, 법적 근거, 첨부된 증적 파일을 검토합니다.
- 같은 판정이 반복되는 항목은 목록에서 체크박스로 선택한 뒤 `일괄 판정`으로 한 번에 처리합니다. 이미 판정한 항목은 기본적으로 건너뛰며, `덮어쓰기`를 선택해야 교체됩니다. 결과는 감사로그에 `검토 결과 일괄 판정`으로 기록됩니다.
- `항목 상세` 우측 상단의 위·아래 버튼 또는 `Alt`+`↑`/`↓`로 다음·이전 항목으로 이동합니다. 검색어와 필터가 적용된 목록 순서를 따르며, 현재 위치가 `34 / 134`처럼 표시됩니다. 답변을 입력하는 중에도 동작합니다.
- `보안 담당자 검토` 섹션에서 다음을 판정합니다:
  - **최종 적용 여부**: 작성자 판단 유지 또는 `Y`/`N`/`N/A`로 조정
  - **검토 결과**: `적합(COMPLIANT)`, `조건부 적합(CONDITIONAL)`, `미흡(INSUFFICIENT)`, `부적합(NON_COMPLIANT)`, `N/A 인정(NA_ACCEPTED)`, `재확인(RECHECK)`
  - **증적 적정성**: `적정(ADEQUATE)`, `일부 보완(PARTIAL)`, `부적정(INADEQUATE)`
  - **검토 의견 및 후속조치** 작성 후 `검토 저장` 클릭

### ⚠️ 3. 항목 보완 요청 및 검증
- 미흡한 항목은 `보완 요청` 버튼을 눌러 보완 사유와 완료 기한을 지정합니다.
- 요청자가 조치를 완료하면 `조치 검증` 버튼을 눌러 상태를 `VERIFIED`로 변경합니다.
- 검증이 끝난 보완 요청은 닫힙니다. 이미 조치 완료했거나 검증된 요청에 같은 조작을 다시 하면 거부되며, 추가 보완이 필요하면 **새 보완 요청**을 발행하세요.
- 모든 항목 검토가 끝나면 `검토 완료` 버튼을 누릅니다. **반려할 때에도 모든 항목에 판정이 있어야 합니다.** 반려가 "전체에 대한 인상"이 아니라 무엇을 확인했는지에 대한 기록으로 남아야 하기 때문입니다. 미검토 항목이 있으면 몇 건이 남았는지와 함께 거부되며, 반복되는 판정은 `일괄 판정`으로 한 번에 처리할 수 있습니다.
- `검토 완료` 버튼 옆에 **남은 것**(미검토 · 미검증 보완 · 판정 후 변경)이 건수로 표시됩니다. 버튼을 눌러 거절당한 뒤에 확인할 필요가 없습니다.
- 미완료(`VERIFIED`가 아닌) 보완 요청이 남아 있어도 검토를 완료할 수 없습니다.
- **판정 이후에 답변이나 증적이 바뀐 항목**이 남아 있어도 검토를 완료할 수 없습니다. 보완 요청을 내면 심의 전체가 작성자에게 돌아가므로 요청하지 않은 항목까지 수정될 수 있고, 그 전에 내린 판정은 지금 화면에 있는 답변을 본 판정이 아닙니다. 증적을 새로 올리거나 새 버전으로 교체하거나 삭제한 경우도 같습니다(증적 적정성도 판정의 일부입니다). 해당 항목에는 빨간 `검토 후 답변 변경` 뱃지가 붙고 필터의 `답변 변경됨`으로 모아 볼 수 있으며, 다시 읽고 `검토 저장`을 누르면 해제됩니다. 검토 완료가 거부될 때에는 무엇이 몇 건 남았는지 함께 알려 줍니다.

## 4. 승인자 (Approver) 실무

- 본인이 신청한 심의는 본인이 검토하거나 승인할 수 없습니다. 검토 시작·판정·최종 승인 모두 거부되며, 다른 검토자나 승인자가 맡아야 합니다.
- 관리자 설정에서 `승인 프로세스`가 켜져 있는 경우, 검토가 완료된 건은 `APPROVAL_PENDING` 상태로 승인자에게 전달됩니다.
- 심의 상세 상단의 `최종 승인` 또는 `반려` 버튼을 클릭하고 의견을 남겨 의사결정을 완료합니다.
- 항목 판정 시 `후속조치`를 적으면 `조치 기한`이 필요합니다(기한 없이 저장하면 422로 거절됩니다). 기한이 없으면 알림도 지연 판정도 동작하지 않아, 약속만 남고 아무도 챙기지 않는 상태가 되기 때문입니다. 기한 7일 전부터, 그리고 기한이 지난 뒤에는 심의 요청자에게 알림이 발송됩니다(같은 항목은 최대 주 1회). 기한이 지나면 리포트에서 `기한 초과`로 표시되므로, "3개월 내 보완" 같은 약속이 실제로 추적됩니다.
- 검토자가 항목별로 남긴 `조치 사항`은 심의 리포트의 `미조치 항목`에 심의 전체가 모여 표시됩니다. 조치를 마쳤으면 `조치 완료`를 눌러 이행 결과를 남기고 종료합니다. 종료된 항목은 목록에서 빠지며 `이행 완료 포함`으로 확인할 수 있고, 잘못 종료했다면 `해제`로 되돌립니다. 원 검토자가 아니어도 보안 담당자면 처리할 수 있습니다. 조건부 적합으로 통과시키며 약속한 후속 조치를 팀 단위로 추적할 때 사용하며, Excel 리포트에도 같은 시트로 포함됩니다.
- 승인자가 지정되지 않은 채 승인 대기로 넘어온 건(제출 이후에 승인 프로세스를 켠 경우)은 승인자 권한을 가진 누구나 결재할 수 있으며, 실제로 결재한 사람이 승인자로 기록됩니다.
- 지정된 승인자가 퇴사 등으로 결재할 수 없으면 시스템 관리자가 승인 대기 상태에서 승인자를 다른 사람으로 변경할 수 있습니다. 변경은 감사로그에 남고 새 승인자에게 알림이 발송됩니다.

## 5. 심의 결과물 내보내기 (Export)

심의 상세 상단의 내보내기 버튼을 통해 3가지 형식의 최종 보고서를 다운로드할 수 있습니다:

| 포맷 | 파일 확장자 | 내용 및 용도 |
| :--- | :--- | :--- |
| **Excel** | `.xlsx` | 전 항목 체크리스트, 자체 판단, 검토 결과와 `증적 목록` 시트(파일명·버전·SHA-256) |
| **PDF** | `.pdf` | 감사 및 대외 제출용 공식 보안성 심의 완료 증명서 (A4). 항목별 첨부 증적과 해시 포함 |
| **ZIP** | `.zip` | 심의 보고서와 암호화 복호화된 전체 첨부 증적 파일 압축 패키지 |

## 6. 알림과 개인 계정 관리

### 🔔 알림
- 상단 바의 종 아이콘에 읽지 않은 알림 수가 표시되며 1분마다 자동 갱신됩니다.
- 알림 화면에서 개별 `읽음` 또는 `모두 읽음`으로 정리하고, `읽지 않음만`과 유형 필터로 좁혀 볼 수 있습니다.
- 심의 관련 알림에는 `심의 열기` 링크가 있어 해당 심의로 바로 이동합니다.
- `수신 설정`에서 유형별로 이메일을 끄거나, 즉시 수신 대신 **하루 한 번 요약**으로 바꿀 수 있습니다. 인앱 알림은 설정과 관계없이 항상 남습니다.
- 보존 기간(기본 1825일)이 지난 알림은 자동으로 정리됩니다.

### 📋 내 차례
- 대시보드 상단의 `내 차례` 목록에는 지금 본인이 처리해야 하는 심의만 모입니다. 작성 중인 심의, 보완 요청을 받은 심의, 배정된 검토·승인 건이 역할에 따라 표시됩니다.
- 심의 목록 화면의 `내 차례` 칩으로 같은 조건을 적용해 전체 목록을 볼 수 있습니다.
- 보완 조치 기한이 임박하거나 지나면 대시보드에 별도 표시되고 알림도 발송됩니다.

### 🔐 2단계 인증 (로컬 계정)
- `개인 > 계정 보안`에서 인증 앱(Google Authenticator 등)을 등록합니다. 화면의 비밀키를 앱의 **수동 입력**에 붙여 넣고, 표시되는 6자리 코드로 활성화합니다.
- 활성화하면 다른 기기의 세션이 모두 종료되고, 이후 로그인 시 비밀번호와 6자리 코드를 함께 입력합니다.
- 같은 화면에서 현재 로그인된 기기 목록을 확인하고 개별 또는 일괄 종료할 수 있습니다.
- 기기를 분실했다면 시스템 관리자에게 초기화를 요청하세요.

### 🔑 비밀번호 변경 (로컬 계정)
- `개인 프로필` 화면의 `비밀번호 변경` 카드에서 현재 비밀번호 확인 후 12자 이상의 새 비밀번호로 변경합니다.
- 변경하면 **현재 사용 중인 브라우저를 제외한 모든 로그인 세션이 즉시 종료**되고 로그인 실패 잠금 카운터도 초기화됩니다.
- SSO(OIDC) 계정은 이 카드가 표시되지 않으며 사내 인증 서버에서 변경합니다.
- 비밀번호를 잊었거나 로그인 실패로 잠긴 경우 시스템 관리자에게 임시 비밀번호 재발급 또는 잠금 해제를 요청하세요.

## 7. Excel 가져오기 (체크리스트 관리자)

1. `.xlsx` 파일을 올리면 Sheet별로 헤더 행과 컬럼 매핑을 자동 인식합니다. 실제 파싱 결과가 가장 많은 Sheet가 먼저 선택됩니다.
2. **가져오기 결과 미리보기**에서 생성될 항목을 그대로 확인합니다. 함께 표시되는 안내로 다음을 미리 알 수 있습니다.
   - 보안요건과 점검항목이 모두 비어 건너뛸 행 수
   - 항목코드가 없어 자동 부여될 항목 수
   - 중복 코드에 `-DUP2` 접미사가 붙을 항목
   - 매핑되지 않은 컬럼
3. 컬럼 매핑이 잘못되었다면 왼쪽에서 직접 지정한 뒤 미리보기를 다시 확인합니다.
4. 잘못 가져왔다면 템플릿 목록에서 삭제할 수 있습니다. **게시하거나 심의에 사용된 뒤에는 삭제할 수 없으므로**, 게시 전에 미리보기로 충분히 확인하세요.
