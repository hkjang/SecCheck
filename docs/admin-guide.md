# SecCheck 관리자 운영 가이드 (Admin Guide)

`SecCheck`는 오프라인 폐쇄망 및 엔터프라이즈 환경에서 외부 의존성 없이 안정적으로 동작하도록 설계된 보안 검토 플랫폼입니다.

---

## 1. 런타임 환경변수 4종

서비스 구동 시 필요한 환경변수는 정확히 다음 4개뿐이며, 그 외 모든 정책은 관리자 웹 콘솔에서 런타임으로 관리됩니다:

| 환경변수명 | 필수 여부 | 설명 | 예시 |
| :--- | :---: | :--- | :--- |
| `POSTGRES_DSN` | **필수** | PostgreSQL 연결 DSN (`sslmode=verify-full` 권장) | `postgres://seccheck:pass@postgres:5432/seccheck?sslmode=disable` |
| `BOOTSTRAP_ADMIN` | **필수** | 초기 로컬 관리자 아이디 | `admin` |
| `BOOTSTRAP_ADMIN_PASSWORD` | **필수** | 초기 관리자 비밀번호 (최소 12자 이상) | `ComplexPassword123!` |
| `ENCRYPTION_KEY` | **필수** | 비밀값 및 데이터 키 암호화용 32바이트 Master Key | `01234567890123456789012345678901` |

> **부트스트랩 계정의 역할**: 최초 기동 시에만 7대 역할 중 6개(감사자 포함)를 모두 부여합니다. 이후 재기동은 **`SYSTEM_ADMIN`만 보장**하며, 운영자가 떼어낸 검토자·승인자 등의 역할은 다시 붙이지 않습니다. 비밀번호도 이미 설정된 계정에는 덮어쓰지 않습니다. 계정을 잃어버린 경우에는 `seccheck admin-recover`를 사용하세요.

## 2. Keycloak OIDC SSO 엔터프라이즈 연동

`SecCheck`는 표준 OpenID Connect Discovery를 통해 사내 Keycloak과 원클릭으로 연동됩니다.

1. **Keycloak Client 설정**:
   - Client Type: `OpenID Connect`
   - Client Authentication: `ON` (Confidential)
   - Standard Flow: `ON`
   - Valid Redirect URIs: `https://<seccheck-host>/api/v1/auth/oidc/callback`
2. **관리자 콘솔 설정 (`/admin/settings` → `Keycloak OIDC`)**:
   - `Keycloak / OIDC SSO 활성화` ON
   - **Issuer URL**: `https://keycloak.company.internal/realms/enterprise`
   - **Client ID** & **Client Secret**: Keycloak 발급 자격증명 입력 (AES-256-GCM 암호화 보관)
   - **Callback URL**: `https://seccheck.company.internal/api/v1/auth/oidc/callback`
   - **사용자명 Claim**: `preferred_username`
   - **기본 역할**: `REQUESTER` (그룹 매핑에 해당하지 않는 사용자에게 부여)
   - **그룹 Claim**: `groups` (Keycloak Client에 group membership mapper를 추가해야 토큰에 포함됩니다)
   - **그룹 → 역할 매핑**: 아래 참조
3. **연결 테스트**:
   - `Discovery 연결 테스트` 버튼을 클릭하여 엔드포인트 도달 가능 여부를 실시간 검증합니다.

### 그룹 → 역할 매핑

매핑을 하나라도 지정하면, 로그인할 때마다 IdP 그룹을 기준으로 해당 계정의 역할을 다시 맞춥니다.

- 그룹 이름은 `/security-reviewers`처럼 앞에 `/`가 있어도 되고 없어도 되며 대소문자를 구분하지 않습니다.
- 한 그룹에 여러 역할을 매핑할 수 있고, 여러 그룹에 속하면 역할이 합쳐집니다.
- **그룹에서 빠지면 다음 로그인에 해당 역할을 잃습니다.** 매핑을 쓰지 않으면 최초 로그인 시 기본 역할만 부여하고 이후에는 손대지 않으므로, 퇴사자 권한 회수를 사람이 직접 해야 합니다.
- 매핑된 어느 그룹에도 속하지 않으면 기본 역할이 부여됩니다.
- 매핑으로 부여할 수 없는 역할(현재 `SYSTEM_ADMIN`)은 동기화 대상이 아니므로, 관리자 화면에서 직접 부여한 값이 그대로 유지됩니다.

그룹 매핑으로 역할이 실제로 바뀌면 `디렉터리 역할 동기화` 감사 이벤트가 변경 전후 역할과 함께 기록됩니다. 변화가 없는 로그인은 기록하지 않습니다. 또한 로그인마다 토큰에서 읽은 그룹 목록이 서버 로그(`oidc` 구성요소)에 남으므로, 역할이 부여되지 않을 때 **Keycloak Client에 group membership mapper가 없어 그룹이 아예 오지 않는 경우**와 매핑 이름이 틀린 경우를 구분할 수 있습니다.

**시스템 관리자는 그룹으로 부여할 수 없습니다.** 역할 동기화는 사람의 확인 없이 로그인마다 자동으로 일어나므로, 디렉터리 그룹을 편집할 수 있는 사람이 감사 시스템의 관리자가 되는 경로를 만들지 않기 위한 결정입니다. 관리자는 이 제품 안에서 명시적으로 부여하고 감사로그에 남깁니다.

## 3. RBAC 7대 역할 체계

| 역할 코드 | 한글 명칭 | 권한 범위 |
| :--- | :--- | :--- |
| `SYSTEM_ADMIN` | **시스템 관리자** | 서비스 설정, 사용자 및 역할 관리, 감사로그 열람 및 체인 검증 |
| `TEMPLATE_ADMIN` | **체크리스트 관리자** | 템플릿 생성/편집/게시, Security Control 등록, Excel 가져오기 |
| `SECURITY_REVIEWER` | **보안 담당자** | 보안 검토 Queue 조회, 검토 시작, 판정, 보완 요청 및 검증 완료 |
| `APPROVER` | **승인자** | 최종 승인 및 반려 의사결정 권한 |
| `REQUESTER` | **심의 요청자** | 신규 심의 생성, 체크리스트 작성, 증적 업로드, 제출 및 재제출 |
| `CONTRIBUTOR` | **공동 작성자** | 배정된 심의의 체크리스트 공동 작성 및 증적 첨부 |
| `AUDITOR` | **감사자** | 모든 심의 및 감사로그 읽기 전용 열람 권한 |

> **역할을 회수하거나 계정을 비활성화할 때**: 그 사람이 맡고 있던 심의는 담당자 이름이 그대로 남지만 본인은 아무 조치도 할 수 없습니다. 서비스는 이런 심의를 **담당자 없는 심의로 취급**해 다른 검토자·승인자의 `내 차례` 대기열에 다시 올리고, 심의 상세에서 `검토 이어받기`로 담당을 넘겨받을 수 있게 합니다. 정체 알림도 처리할 수 없는 담당자 대신 검토자 전체에게 발송됩니다. 별도의 재배정 작업 없이도 심의가 멈추지 않습니다.

## 4. 파일 업로드 보안 & ClamAV 안티바이러스

- **Magic/MIME & 확장자 교차 검증**: 파일 확장자 위변조(예: `.exe`를 `.pdf`로 변경)를 서버 레벨에서 차단합니다.
- **AES-256-GCM 암호화 보관**: 모든 증적은 서버 디스크에 UUID 파일명으로 암호화되어 저장됩니다.
- **ClamAV 악성코드 검사**:
  - 관리자 설정에서 `ClamAV 악성코드 검사` 활성화 및 `clamav:3310` 데몬 주소 입력
  - 주소 옆 `연결 테스트` 버튼이 clamd에 `PING`을 보내 응답을 확인합니다. 잘못된 주소를 저장하면 업로드가 계속 `PENDING`으로 남아 제출이 막히므로, **켜기 전에 확인**하십시오(시도는 `ClamAV 연결 테스트` 감사 이벤트로 남습니다).
  - ClamAV 검사 실패 또는 악성코드 탐지 시 파일 업로드는 즉시 차단(Fail-Closed)됩니다.
  - 업로드 후 비동기 검사에서 탐지된 증적은 체크리스트에서 즉시 제거되고 업로더에게 알림이 갑니다. 이때 감사로그에 `증적 악성코드 격리`(`QUARANTINE_EVIDENCE`) 이벤트가 남아 어떤 파일이 왜 사라졌는지 확인할 수 있습니다.

---

정기 점검(매시간)이 멈추면 기한 알림·정체 알림·증적 표본 검사·감사로그 체인 검증·보존 기간 정리가 모두 함께 멈춥니다. `관리 > 시스템 정보`의 `정기 점검` 카드에서 마지막 완료 시각을 확인할 수 있고, 3시간 넘게 기록이 없으면 붉은 배지로 표시됩니다. Prometheus를 쓰는 경우 `seccheck_maintenance_last_run_seconds`에 경보를 거십시오.

## 5. 암호학적 해시 체인 감사로그 무결성 검증

서비스는 **매시간 자동으로** 마지막 검증 지점 이후에 추가된 이벤트를 다시 해시해 체인을 확인합니다. 실패하면 서버 로그에 `ERROR`가 남고 시스템 관리자에게 `감사로그 체인 검증 실패` 알림이 갑니다(같은 알림은 6시간에 한 번으로 제한). 실패한 구간은 검증 완료로 표시되지 않으므로, 원인을 확인하고 조치한 뒤 화면에서 `전체 재검증`을 실행하십시오.

- **해시 체인 구조**:
  - 모든 행위(로그인, 심의 생성, 수정, 제출, 판정, 승인, 설정 변경, 키 회전)는 이전 이벤트의 해시(`prev_hash`)와 결합되어 SHA-256 해시 체인을 형성합니다.
  - 데이터베이스 직접 조작이나 위변조가 발생할 경우 체인이 즉시 깨집니다.
- **체인 검증 실행 (`/admin/audit`)**:
  - `체인 검증` 버튼을 누르면 서버가 전체 이벤트의 암호학적 링크를 전수 검사하여 `"N개 감사 이벤트의 해시 체인이 유효합니다."` 결과를 반환합니다.
  - 검증에 실패하면 **활성 상태의 시스템 관리자 전원**에게 `감사로그 무결성 실패` 알림이 가고, 알림 설정이 `즉시`인 관리자에게는 메일도 발송됩니다. 알림을 누르면 검증이 멈춘 감사 이벤트로 이동합니다. 버튼을 누른 사람만 결과를 보는 구조가 아닙니다.

## 7. 로그인 보호와 계정 잠금 (`/admin/settings` → `접근 보안`)

| 설정 | 기본값 | 설명 |
| :--- | :---: | :--- |
| `login_rate_limit_per_minute` | `30` | IP별 분당 로그인 **실패** 허용 횟수. 성공한 로그인은 계산하지 않습니다 |
| `max_login_failures` | `5` | 계정 잠금까지 허용할 연속 실패 횟수. `0`이면 잠금 미사용 |
| `lockout_minutes` | `15` | 자동 잠금 유지 시간 |
| `idle_timeout_minutes` | `0` | 유휴 세션 만료. `0`이면 세션 시간까지 유지. 값이 있으면 사용자 화면이 만료 2분 전(짧은 정책은 절반 시점)에 `계속 사용` 여부를 묻습니다. 알림 배지 폴링은 활동으로 세지 않으므로 자리를 비운 세션은 그대로 만료됩니다 |
| `trusted_proxies` | (비어 있음) | X-Forwarded-For를 신뢰할 Reverse Proxy IP 또는 CIDR |
| `require_totp_for_admins` | `false` | 관리자·검토자·승인자 계정에 일회용 코드(TOTP) 요구 |

- 잠금은 `LOGIN_LOCKED` 감사 이벤트로 남고 `seccheck_accounts_locked` 지표로 관측합니다.
- 잠긴 계정은 `/admin/users` 화면의 `잠금 해제` 버튼으로 즉시 복구하며, 해제 역시 감사로그에 기록됩니다.
- **비활성화 전 확인**: 비활성화 버튼을 누르면 그 계정이 아직 맡고 있는 진행 중 심의(요청자·검토자·승인자)와 미이행 후속조치 건수를 먼저 보여 줍니다. 비활성화해도 그 자리는 비워지지 않으므로, 남은 것이 있으면 먼저 인계하십시오.
- 퇴사자의 심의가 남아 있으면 해당 심의 화면의 `요청자 인계`로 다른 요청자에게 넘기십시오. 계정을 비활성화하면 배정된 항목의 담당자는 자동으로 풀리지만, 심의의 요청자 자리는 인계해야 알림과 후속조치가 살아 있는 계정으로 갑니다.
- 비밀번호를 잊은 로컬 계정은 같은 화면의 `비밀번호` 버튼으로 임시 비밀번호를 발급합니다. `임의 생성` 버튼으로 안전한 값을 만들고, 재설정하면 해당 사용자의 모든 세션이 종료되며 잠금도 함께 풀립니다. SSO 계정에는 사용할 수 없습니다.
  - **발급한 비밀번호는 본인이 한 번 바꿔야 합니다.** 계정 생성과 재설정으로 정해 준 값은 관리자도 알고 있는 값이므로, 그 계정은 로그인 후 비밀번호를 바꾸기 전까지 다른 화면과 API를 쓸 수 없습니다(403 `PASSWORD_CHANGE_REQUIRED`). 바꾸면 즉시 정상 사용으로 돌아갑니다. API 키 인증에는 적용되지 않으며, 설치 시 만든 최초 관리자 계정도 대상이 아닙니다.
- 사용자 목록은 이름·아이디·이메일·부서·역할로 검색하고 `로그인 잠김`, `비활성`, `로컬/SSO`로 좁혀 볼 수 있습니다.
- 잠금은 신규 로그인만 차단하고 이미 열려 있는 세션은 종료하지 않으므로, 제3자가 잠금을 이용해 사용자를 강제 로그아웃시킬 수 없습니다.
- **Reverse Proxy 뒤에 배치하는 구성에서는 `trusted_proxies` 설정이 필수입니다.** 비워 두면 모든 요청이 Proxy 한 IP로 집계되어 요청 제한과 감사로그의 접속 IP가 조직 전체 단위로 묶입니다.

## 8. 데이터 보존 자동 정리

서비스 시작 1분 뒤부터 매시간 다음을 5,000행 단위로 정리하므로 별도 cron이 필요하지 않습니다.

- 만료된 세션과 OIDC state
- `COMPLETED` 7일, `FAILED` 90일이 지난 알림 Job
- 일반 설정 `retention_days`(기본 1825일)가 지난 서버 로그와 인앱 알림
- 잠금 시간이 지난 계정의 로그인 실패 카운터

감사로그는 해시 체인 검증을 위해 자동 삭제하지 않습니다. 정리 결과는 `maintenance` component 서버 로그에서 확인합니다.

## 9. 감사로그 조회와 반출

- **필터**: 이벤트 유형(앞부분만 입력해도 하위 이벤트까지 매칭), 사용자명 또는 접속 IP, 기간(시작일·종료일), 표시 건수.
- **상세 보기**: 이벤트 뱃지를 클릭하면 변경 전후 값, 요청 ID, 이전 해시와 이벤트 해시를 전체 확인할 수 있습니다.
- **대상으로 좁히기**: 표의 `대상` 값을 누르면 그 대상(심의·Control·템플릿 등)의 이력만 남습니다. 주소창에 조건이 남으므로 링크로 공유할 수 있고, Security Control 목록의 `이력` 버튼도 같은 화면으로 연결됩니다.
- **이벤트 하나만 보기**: `이벤트 ID` 필터(`event_id`)로 특정 감사 이벤트 한 건만 표시합니다. 무결성 실패 알림의 `해당 감사 이벤트 열기` 링크가 이 필터로 연결됩니다.
- **거부된 시도만 보기**: `결과` 필터(`result=FAILURE`)로 서비스가 거절한 시도만 모아 봅니다. 로그인 실패, 증적 다운로드 거부, **현재 비밀번호가 틀린 비밀번호 변경 시도**가 여기에 들어옵니다.
- **권한 없는 접근 시도**: 역할이 없는 계정이 관리 엔드포인트를 호출하거나, 읽기 전용 API 키로 쓰기를 시도하면 `ACCESS_DENIED` 이벤트가 남습니다(요청 경로·요구 역할·API 키 여부 포함). 정상 권한으로 한 작업은 남기지 않습니다.
- **더 오래된 이벤트 보기**: 목록은 한 번에 최대 200건을 보여 주고, 더 남아 있으면 아래에 `더 보기`가 나타납니다. 누르면 그 다음 구간을 이어서 붙입니다(필터를 바꾸면 처음부터 다시 읽습니다). API에서는 `offset`으로 같은 동작을 하며 응답의 `has_more`가 남은 여부를 알려 줍니다.
- **CSV 내보내기**: 현재 필터 그대로 최대 50,000행을 UTF-8 BOM CSV로 내려받습니다. Excel에서 바로 열리며, 내보내기 행위 자체도 `EXPORT_AUDIT` 이벤트로 감사로그에 남습니다.
  `=`, `+`, `-`, `@`로 시작하는 값은 Excel이 수식으로 해석하므로 앞에 작은따옴표를 붙여 내보냅니다. Excel 화면에는 보이지 않고, 텍스트 편집기나 스크립트로 읽을 때만 나타납니다.

## 10. 서버 로그 조회

- 메시지, 구성요소, 요청 ID, 구조화 필드(경로·상태코드 등)를 한 번에 검색합니다.
- `10초 자동 새로고침`을 켜면 장애 대응 중 화면을 유지한 채 최신 로그를 추적할 수 있습니다.
- 감사로그의 요청 ID를 서버 로그 검색창에 붙여 넣으면 동일 요청의 처리 결과를 바로 연결해 볼 수 있습니다.

## 11. 2단계 인증 운영

- 사용자는 `개인 > 계정 보안`에서 등록합니다. 서버가 비밀키와 `otpauth://` URI를 제공하고, 인증 앱의 **수동 입력**으로 등록합니다. 외부 QR 생성 서비스를 호출하지 않기 위한 설계입니다.
- 활성화 시 해당 사용자의 다른 세션이 모두 종료됩니다.
- 기기 분실 시 `/admin/users`의 `코드 초기화` 버튼으로 복구합니다. 초기화하면 2단계 인증이 해제되고 모든 세션이 종료되므로, 사용자가 다시 등록하도록 안내하세요.
- SSO 로그인이 실패하면 사용자는 로그인 화면으로 돌아오고 화면에 이유가 표시됩니다(연결 실패·거부·IdP 오류 코드). 서버 로그와 감사로그에는 `LOGIN_FAIL`(`target_type=OIDC`)로 남으므로, 사용자가 알려 준 코드로 원인을 맞춰 볼 수 있습니다.
- `require_totp_for_admins`를 켜면 대상 사용자는 등록을 마치기 전까지 계정 보안 화면 외의 API가 모두 403으로 차단됩니다.

## 12. 심의 목록 운영 기능

- 필터: 상태(복수 선택 포함), 검색어, 담당 부서, 보안 담당자, 생성일 범위, `내 차례`, `기한 초과`, `오픈 임박`(오픈 예정일이 2주 이내인데 심의가 끝나지 않은 건. 대시보드의 `미완료 N건`과 같은 조건입니다).
- 정렬: 최근 변경·생성일·오픈 예정일·심의번호·서비스명·상태.
- 페이지네이션과 총건수를 함께 반환하므로 오래된 심의가 목록에서 사라지지 않습니다.
- CSV 내보내기는 현재 필터를 그대로 적용하며 `EXPORT_REVIEW_LIST` 감사 이벤트로 기록됩니다.
- 후속조치 등록부는 화면에 최대 500건까지 표시하고, 그보다 많으면 `표시 건수 / 전체 건수`와 안내 문구를 함께 보여 줍니다. 전체 목록은 Excel 내보내기로 받으십시오(최대 50,000행).

대시보드의 `대기열 상태` 카드는 **담당자가 지정되지 않은 심의**와 **3일 이상 멈춘 심의** 수를 보여 주며, 각각 목록의 `담당자 없음`·`정체` 필터로 연결됩니다. 정체 기준일은 `심의 정체` 알림과 같은 값을 씁니다.

## 12-2. 본인 심의 처리 금지 (`allow_self_review`)

신청자 본인은 자신이 올린 심의를 검토하거나 승인할 수 없습니다. 검토 시작, 항목 판정, 보완 요청, 최종 승인이 모두 거부되며 `SELF_REVIEW_FORBIDDEN`으로 응답합니다. 심의를 요청한 사람은 그 심의의 중립적인 판정자가 아니라는 것이 이 프로세스의 전제이기 때문입니다.

보유자가 한 명뿐인 역할은 시스템 정보 화면의 `역할 보유자` 표에 `1명뿐`으로 표시됩니다. 그 사람이 신청자인 심의는 처리할 수 없으므로, 검토자와 승인자는 두 명 이상 두는 것을 권장합니다.

담당자가 한 명뿐이라 같은 계정이 신청과 검토를 모두 해야 하는 설치는 서비스 설정 > 워크플로에서 `본인이 신청한 심의를 본인이 검토·승인 허용`을 켜서 예외를 둘 수 있습니다. 기본값은 금지입니다.

## 11-1. 체크리스트 항목 입력 길이

항목코드 40자, 제목 300자, 섹션 100자, 질문·안내·예시 각 4,000자, 근거 2,000자입니다. 심의 작성·검토 화면의 긴 입력란에는 같은 한도가 입력창 자체에 적용되어, 한도를 넘겨 붙여넣을 수 없고 90%를 넘으면 남은 글자 수가 표시됩니다. 항목은 그 항목이 적용되는 **모든 심의의 스냅샷으로 복사**되므로, 한 번 길게 넣은 값이 이후 모든 심의에 그대로 복제됩니다. Excel 가져오기는 워크북 전체를 실패시키는 대신 넘치는 값을 잘라내고, 마법사 미리보기에서 몇 건이 잘리는지 알려 줍니다.

항목코드는 한 버전 안에서 유일해야 합니다. 같은 코드를 다시 추가하면 `이 버전에 같은 항목코드가 이미 있습니다`로 거부되고, Excel 가져오기는 **저장되는 40자 기준으로** 중복을 판정해 뒤 항목에 `-DUP2` 같은 접미사를 붙이고 마법사의 경고 목록에 코드를 표시합니다. 40자를 넘는 긴 코드끼리 앞부분이 같아도 서로 다른 항목으로 저장됩니다.

PDF 내보내기에 필요한 한글 글꼴이 image에 있는지도 여기서 보입니다. 업그레이드 직후와 장애 대응 시 가장 먼저 여는 화면입니다.

## 14. 작업 큐 (`/admin/jobs`)

| 유형 | 내용 | 실패 시 |
| :--- | :--- | :--- |
| `SEND_EMAIL` | 인앱 알림의 이메일 발송 | SMTP 오류는 5회 재시도 후 `FAILED`. 수신자에게 이메일 주소가 없거나 이메일 발송이 꺼져 있는 등 **재시도로 해결되지 않는 경우는 재시도 없이 `COMPLETED`로 종료**하고 사유를 `마지막 오류`에 남깁니다(인앱 알림은 그대로 남습니다) |
| `SCAN_EVIDENCE` | 증적 악성코드 검사 | 5회 재시도 후 `FAILED`이며 증적은 `ERROR`. 재시도하면 `PENDING`으로 복귀 |

- 상태 필터와 10초 자동 새로고침을 제공하며, 개별 재시도와 `실패 전체 재시도`를 지원합니다.
- 작업 큐와 서버 로그는 최근 200건까지만 표시하며, 잘린 경우 목록 아래에 그 사실을 알립니다. 더 오래된 기록은 상태·레벨·검색어로 조건을 좁혀 확인하십시오.
- `검사 대기 증적` 카드는 다운로드·제출이 막혀 있는 증적 수입니다. 이 값이 줄지 않으면 clamd 연결을 먼저 확인하세요.
- 재시도를 모두 소진한 작업이 생기면 시스템 관리자에게 `작업 재시도 소진` 알림이 오고, 마지막 오류 메시지가 함께 표시됩니다.
- 서비스가 작업 처리 도중 재시작되면 그 작업은 `RUNNING`으로 남습니다. 유지보수 스윕(매시)이 **15분 이상 잡혀 있는 `RUNNING` 작업을 자동으로 큐에 되돌리며**, 기다릴 수 없으면 목록에서 바로 재시도할 수 있습니다. 증적 검사가 이 상태로 멈추면 해당 심의는 제출이 막히므로, `검사 대기 증적`이 줄지 않을 때 함께 확인하세요.

## 15. 감사 체인 검증과 증적 무결성

- **체인 검증**: 마지막 성공 지점 이후만 확인하므로 이벤트가 누적돼도 점검 시간이 일정합니다. **전체 재검증**은 복구 직후나 정기 감사 때 사용합니다.
- 검증 실패 시 서버 로그 ERROR와 **모든 시스템 관리자 인앱 알림**이 발생합니다.
- **배포 자체 점검**: `/app/seccheck selftest`로 준비 상태, 로그인, OpenAPI, 게시 템플릿, 감사 체인을 확인합니다. `--full`은 검증 환경에서 심의 생성과 Excel·PDF·ZIP 내보내기, 취소까지 수행하며, 한글 폰트 누락 같은 이미지 패키징 결함은 이 단계에서만 드러납니다. 실패 시 종료 코드 1.
- **증적 무결성**: `/app/seccheck verify-evidence`로 전체 증적을 복호화해 크기와 SHA-256을 대조합니다. `--sample N`으로 표본만, `--json`으로 기계 판독 형식을 출력하며 실패 시 종료 코드 1을 반환합니다.
- **정기 자동 확인**: 유지보수 스윕이 매시 **가장 오래 확인하지 않은 증적 20건**을 실제로 복호화해 크기·해시를 대조합니다(`evidences.verified_at`). 읽을 수 없거나 기록과 다르면 시스템 관리자에게 `증적 무결성 확인 실패` 알림이 가며, 파일명·심의번호·사유가 함께 표시됩니다. 감사 시점이 아니라 **사고 직후에** 알게 하는 것이 목적입니다.

## 16. 검색 인덱스

마이그레이션 004가 `pg_trgm` 확장과 GIN 인덱스를 만들어 부분 일치 검색을 인덱스 스캔으로 전환합니다. 확장 생성 권한이 없으면 경고만 남기고 순차 스캔으로 동작하므로, 데이터가 많은 설치는 DBA에게 `CREATE EXTENSION pg_trgm;`을 요청한 뒤 재기동하십시오.

| 알림 | `테스트 메일 보내기` | 저장된 SMTP 설정으로 본인에게 1통 발송 |

- 사용자별 수신 설정은 알림 화면의 `수신 설정`에서 관리합니다. 유형별 이메일 차단과 `즉시 / 하루 한 번 요약`을 선택할 수 있습니다. 차단한 유형은 즉시 메일과 일일 요약 모두에서 빠지며, 화면의 알림 목록에는 그대로 남습니다.
- `오픈 예정일 임박` 알림: 심의가 끝나지 않았는데 오픈 예정일이 3일 이내로 다가왔거나 이미 지났으면 신청자와 현재 담당자에게 알립니다(같은 건은 3일에 한 번). 오픈 예정일은 심의 완료 여부와 무관하게 서비스가 열리는 날이므로, 늦기 전에 결정할 수 있게 하는 것이 목적입니다.
- `심의 정체` 알림: 제출·재제출·검토 중·승인 대기 상태로 3일 이상 움직이지 않은 심의를 담당자에게 알립니다. 같은 건은 3일에 한 번만 알립니다. 담당자가 지정되지 않은 건은 보안 담당자 전원에게 **한 통으로 묶어** 보냅니다(건수와 가장 오래된 건의 대기 일수 포함). 심의마다 따로 보내면 밀린 큐에서 알림이 폭주해 아무도 보지 않게 되기 때문입니다.
- 기한 알림(보완 조치·후속조치)과 증적 악성코드 탐지 알림도 `즉시` 수신자에게는 이메일로 발송됩니다. 작업 큐 정체·작업 재시도 소진 알림은 이메일 경로 자체가 멈췄을 수 있으므로 인앱 알림으로만 전달합니다.
- **인앱 알림은 사용자 설정과 무관하게 항상 기록됩니다.** 수신 설정은 이메일 발송 여부만 바꿉니다.
- 요약 수신자에게는 즉시 메일이 나가지 않고, `digest_hour` 이후 하루 한 번 모아서 발송됩니다. 하루의 기준은 `표시 시간대` 기준 자정입니다.

## 18. Rule Engine 시뮬레이터 (`/templates/rules`)

적용 규칙(`applicability_rule`)은 지금까지 심의를 실제로 만들어 봐야 결과를 알 수 있었고, 게시된 버전은 수정할 수 없어 잘못된 규칙을 되돌리기 어려웠습니다.

- 서비스 유형·변경 유형·노출 범위·중요도와 9개 특성 토글만 입력하면 배정될 항목과 제외될 항목을 즉시 계산합니다.
- 제외 사유를 **분류 불일치**와 **적용 규칙 불만족**으로 구분해 표시하므로, 규칙이 잘못됐는지 분류가 잘못됐는지 바로 판단할 수 있습니다.
- 심의를 생성하지 않으므로 몇 번이든 반복해도 데이터가 남지 않습니다.
- 체크리스트 관리자와 보안 담당자가 사용할 수 있습니다.
- 시뮬레이션 결과 맨 위에 `적용 규칙 오류` 표가 나옵니다. 예전에 저장된 규칙이 심의 입력에 없는 이름을 가리키고 있으면 그 항목은 어떤 심의에도 배정되지 않으므로, 해당 항목과 원인을 함께 보여 줍니다. 게시된 버전은 수정할 수 없으니 새 버전에서 고쳐야 합니다.
- 항목을 저장할 때 적용 규칙을 검사합니다. 심의 입력 항목에 없는 이름이나 지원하지 않는 연산자를 쓰면 422로 거절하고 어느 부분이 문제인지 알려 줍니다. 규칙이 절대 참이 될 수 없으면 그 항목은 어느 심의에도 배정되지 않고, 그 사실을 아무도 통보받지 못하기 때문입니다.

## 19. 시간대

일반 설정의 `표시 시간대`가 화면·내보내기·요약 메일과 기한 판정(지연·임박), 기간 필터(심의 목록·감사로그·기간 리포트), 등록부에 표시되는 날짜에 모두 적용됩니다. CSV 내보내기의 시각도 같은 시간대로 기록됩니다. IANA 이름(`Asia/Seoul`)을 사용하며 저장 시 검증합니다. 컨테이너는 UTC로 동작하고 시간대 데이터가 바이너리에 내장되어 있어, 호스트 시간대 설정과 무관하게 모든 노드가 동일하게 표시합니다.

## 20. 심의 리포트 (`/reports`)

월간·분기 보고에 바로 쓸 수 있는 집계 화면입니다. 기본 범위는 이번 달이며 `이번 달 / 최근 3개월 / 최근 1년` 버튼과 부서 필터를 제공합니다.

| 집계 | 내용 |
| :--- | :--- |
| 총괄 | 신규·제출·완료(승인/종료)·반려·진행 중 건수 |
| 처리 기간 | 최초 제출 → 최종 승인까지의 평균·중앙값·90분위 일수 |
| 상태별 / 부서별 | 건수와 부서별 평균 처리일 |
| 검토 결과 분포 | 항목 단위 판정(적합·조건부·미흡·부적합·N/A 인정) 집계 |
| 반복 미흡 항목 | 미흡·부적합 판정이 많은 항목 상위 20개 |
| 경과 기간 | 진행 중 심의를 최근 변경 이후 경과로 구분 (3일 미만 / 3~7일 / 7~14일 / 14일 이상) |

`Excel 리포트` 버튼으로 6개 시트 워크북을 내려받습니다. 대상 기간과 생성 시각이 설정된 시간대로 기록되며, 내보내기는 `EXPORT_REPORT` 감사 이벤트로 남습니다.

조회 권한: 시스템 관리자, 보안 담당자, 감사자, 승인자.
